## قواعد الإثبات
- [GH] حقيقة تحققت من GitHub أو ملفات الفرع المحدد.
- [PO] قرار صريح من مالك المنتج.
- [PROPOSED] تصميم مستقبلي.
- [USER] تأكيد مباشر من المستخدم لم يُثبت بالضرورة على GitHub.
- [UNV] لا يوجد دليل كافٍ؛ لا يجوز تقديمه كحقيقة.

GitHub هو المرجع لحالة الفروع والـ PRs والـ CI. قرار PO هو المرجع للموافقات. لا يثبت CI موافقة PO، ولا يثبت وجود مسار OpenAPI وجود Controller فعلي.

## فرع PR التوثيق
يستهدف DOC-01/DOC-02 الفرع الأساسي BackendApp حتى تعمل فحوص backend-ci المطلوبة على تغييرات التوثيق. هذا اختيار لبوابة CI وليس إضافة Backend implementation. تبقى التغييرات محصورة في docs/، باستثناء تغيير workflow المحدد صراحةً في نطاق DOC-01.
