1. عربية مصرية واضحة، بتنسيق **RTL** (`<div dir="rtl" style="text-align:right">`).

4. **رسالة كاملة جاهزة لـ ChatGPT** (القواعد + المطلوب + شكل التقرير). الـ PO يطلب دائمًا "كل التفاصيل كاملة" ليرسلها.
5. لا تسأل أكثر من سؤال واحد في الرد الواحد، وتجنب القوائم النقطية عند الاعتذار أو الرفض.

## 2) المشروع والمستودع

- **Repository:** `mosalah00x-source/classic-store-New`
- **فرعا التكامل:** `FrontendApp` (الواجهة) و`BackendApp` (الباك إند + الوثائق). لا تعديل على `main` من هذا العمل **[UNV: وفق V4]**.
- **فرع التوثيق التاريخي:** `docs/project-reference` (اندمج في `BackendApp` عبر PR #31؛ مصيره قيد القرار DOC-BRANCH، **لا يُحذف بدون موافقة الـ PO**).
- **الوثائق المرجعية داخل الريبو:** `docs/project-reference/` (README، ADMIN-0، ADM-1-plan، open-items، tech-debt، `tasks/`)، و`docs/reports/` (ملخصات V2 إلى V5)، و`docs/reference/` (SRS وSQL موحّد)، و`docs/decisions/`، و`docs/ui-reference/` (الـ prototype)، و`docs/api/openapi.yaml` (عقد تصميمي، **ليس دليل تنفيذ**).
- **Prototype المرجعي:** مجلد `docs/ui-reference/` يُشغَّل محليًا على `http://localhost:8000`. صور المنتجات فيه فارغة (بيضاء) أصلًا. لا تُنسخ منه صور.

### التقنيات
- **الواجهة:** Next.js 16 (Turbopack)، next-intl (`ar.json` و`en.json`)، خطوط Cairo وInter (Google Fonts)، mock API عبر `API_MOCKING` و`API_MOCK_SCENARIO` (السيناريوهات: `default` و`many` و`showcase`).
- **الباك إند:** Spring (حزمة `com.classicstore`)، Flyway (V1–V7)، PostgreSQL (schema `store`)، JWT وBCrypt بقوة 12 وRate Limiter لتسجيل الدخول.
- **CI:** `frontend-ci` (Install، Lint، Typecheck، Unit tests، Production build)، و`backend-ci` (ثلاثة فحوص مطلوبة: `api-lint` و`backend` و`verify migrations`).

### بيئة الـ PO المحلية
- Windows وPowerShell (يستخدم `npm.cmd`)، وFirefox (Responsive Design Mode).
- تكبير ويندوز 125% (لقطات الشاشة 1920 بكسل ≈ 1536 CSS).
- Google Fonts يفشل تحميله (شبكة/Firewall)، فيستخدم Next خطًا بديلًا: **تحذير بيئي وليس خطأ**.
- يعمل أحيانًا من نسخة ثانية للمشروع (`classic-store-New-Test`). **أي نسخة جديدة تحتاج `frontend/.env.local` يدويًا** (غير مُتتبَّع في git):
  ```
  API_MOCKING=true
  API_MOCK_SCENARIO=showcase
  ```
  غيابه يعرض «تعذر تحميل التصنيفات/المنتجات» رغم أن الصفحة ترجع 200. بعد أي تغيير في البيئة: أعد تشغيل `npm.cmd run dev`.

## 3) قواعد دائمة (تُنسخ في أي تعليمات لـ ChatGPT)

- التغييرات داخل `/frontend` للواجهة، و`docs/` للتوثيق، وبلا Dependencies جديدة ولا تغيير لعقد الـ API بلا قرار.
- **لا اختراع بيانات.** المصدر لا يوجد ← يتوقف ويسأل. الأدلة تُوسم: **[GH]** و**[PO]** و**[USER]** و**[UNV]**.
- **CI الأخضر لا يعني القبول.** القبول = مطابقة بصرية ضمن النطاق + موافقة PO.
- Draft لكل PR، **ChatGPT لا يدمج ولا يحوّل إلى Ready**، ولا force push.
- اقرأ CI على **Head النهائي بعد كل push** (كل الخطوات) مع Run ID وتطابق الـ SHA. وأي Head يُذكر يُقرأ حيًا.
- ChatGPT لا يدّعي مطابقة بصرية (لا يرى المتصفح). المراجعة البصرية للـ PO.
- كل نص عبر ملفات الترجمة، وCSS بخصائص logical وtokens (لا hex في المكونات). لا يُلمس `next-env.d.ts`.
- راجع كل ملف يدويًا قبل كل push، ومنها كود الاختبارات (ChatGPT لا يشغّلها، وفشل Run #55 كان من Regex).
- **بعد كل دمج: تسجيل المهمة في `docs/project-reference/tasks/`** (PR توثيق صغير). المهمة لا تُسمّى `Done` قبل: PR مدمج + CI ناجح على Merge SHA + توثيق مكتمل + موافقة PO برابط + Visual QA (`Not required` أو `Passed`).

**الأدمن (22 نوفمبر 2026):**
- يعيش داخل نفس تطبيق Next تحت `/admin` بتخطيط مستقل (RTL عربي أولًا).
- الأدوار: **مدير** (`ADMIN` الموجود) و**محرر** (`EDITOR` جديد). لا تسجيل ذاتي للأدمن.
- التصنيفات **مستويان** كما في الـ prototype (يفتح المستوى الثاني في القائمة الرئيسية).
- الحذف **soft delete** (أرشفة).
- الـ Hero والعروض والخدمات من الأدمن في مرحلة لاحقة (ADM-6).
- الطلبات والمستخدمون النهائيون بعد بناء السلة والـ checkout.
- **الاستضافة:** سحابية، لكن بعد اكتمال التجربة المحلية. **تخزين الصور:** محلي في التطوير خلف **storage adapter** قابل للتبديل، واختيار السحابة (S3/Cloudinary/غيره) مؤجل لحين قرار الاستضافة.
- مقترحات اعتمدها الـ PO ضمنيًا عبر رسالة ADMIN-0 (تُراجع في `ADMIN-0.md`): Next كوسيط (BFF) بكوكيز `HttpOnly` دون JWT في المتصفح، الأسعار `price` و`compareAtPrice` (والـ Backend يحسب `discountPercent` و`isNew` خلال 30 يومًا)، فرض عمق مستويين وسجل تدقيق للإضافة فقط، وإنشاء أول مدير بأمر لمرة واحدة بلا كلمة مرور افتراضية.

**مصفوفة الصلاحيات المقترحة (للمراجعة النهائية):** المدير: كل شيء. المحرر: إنشاء وتعديل المنتجات والتصنيفات والنشر وتعديل الأسعار والمخزون (مع تسجيل في audit log). المحرر **لا** يؤرشف ولا يستعيد، ولا يدير المستخدمين والأدوار، ولا الإعدادات، ولا يطّلع على سجل التدقيق.

- **PR #31 اندمج** (Final Head `4ecba73a…`، Merge `67dbd343…`). الـ PO دمجه بنفسه. **لم يُنشر تعليق Visual QA/موافقة على GitHub بعد**، فمهام DOC تبقى `Merged` لا `Done`.
- **Merge-SHA CI لـ #31 (Run #186):** كان قيد التنفيذ، يجب التحقق منه.
- **حالة الباك إند (من جرد ADMIN-0، `BackendApp`):**
  - جدول `store.users` بأدوار: `CUSTOMER` و`ADMIN` و`OPERATIONS` و`WAREHOUSE` و`SUPPORT`. **لا يوجد `EDITOR`.**

  - لا خدمة رفع صور، ولا جدول `audit_log`.
  - التصنيفات فيها `parent_id` وترتيب وتفعيل، **دون قيد على عمق المستويين**.
