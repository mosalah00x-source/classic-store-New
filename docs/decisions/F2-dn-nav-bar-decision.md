# قرار PO — شريط التنقل السفلي `.dn`

**تاريخ القرار:** 2026-11-22 (UTC)  
**المستودع:** `mosalah00x-source/classic-store-New`  
**فرع التوثيق:** `docs/project-reference`  
**طريقة التسجيل:** قرار PO في المحادثة، ويُسجل على GitHub بتعليق مستقل.

## 1. القرار السابق F2 — مُلغى

> `.dn` يبقى في الـ Prototype فقط، ولا يُنقل إلى التطبيق الفعلي.

**الحالة:** مُلغى بالقرار الجديد أدناه.  
**قاعدة الحفظ:** يظل القرار السابق محفوظاً كسجل تاريخي، ولا يُحذف أو يُستبدل بصمت.

## 2. القرار الجديد — بديل قرار F2 السابق

**القرار المعتمد:** تنفيذ `.dn` كشريط تنقّل ظاهر وثابت أسفل الشاشة داخل واجهة التطبيق الفعلية، على غرار التصميم المرجعي، حتى لو كرر بعض روابط Header.

### الروابط

| الرابط في التصميم | الحالة المعتمدة | السلوك |
|---|---|---|
| الرئيسية | نشط | ينتقل إلى الصفحة الرئيسية حسب اللغة |
| المنتجات | نشط | ينتقل إلى صفحة المنتجات حسب اللغة |
| تفاصيل المنتج | معطّل — قريباً | لا يفتح صفحة؛ لا يوجد slug افتراضي معتمد |
| السلة | معطّل — قريباً | يظهر معطّلاً إلى أن تُنفذ صفحة السلة |
| الدفع | معطّل — قريباً | يظهر معطّلاً إلى أن تُنفذ صفحة الدفع |
| تأكيد الطلب | معطّل — قريباً | يظهر معطّلاً إلى أن تُنفذ صفحة تأكيد الطلب |

**ملاحظة تفاصيل المنتج:** رغم وجود مسار تفاصيل المنتج في التطبيق، يتطلب فتحه `slug` لمنتج محدد. لا يعتمد الشريط منتجاً افتراضياً ولا يختار أول منتج تلقائياً؛ يظل الرابط معطّلاً إلى أن يصدر قرار/تصميم يحدد سلوكه.

### المكان والعرض

- المكان: شريط ثابت أسفل الشاشة، كما في التصميم.
- الموبايل: الشريط ظاهر بالكامل؛ إذا ظهر تعارض مع المحتوى أو الفوتر، يُسجل للمراجعة ولا يُخفى أو يُغيّر تلقائياً.
- تكرار روابط Header مقبول وفق قرار PO.

### العنوان

- حذف عنوان «صفحات العرض».
- لا يُستبدل بعنوان آخر.

### زر التصغير

- زر التصغير مفعّل.
- الحالة الافتراضية: مفتوح.
- عند التصغير: تُخفى الروابط ويظل زر التحكم ظاهراً.
- تُحفظ الحالة في `localStorage` بالمفتاح `classic-store:bottom-nav:v1`.
- يجب إحاطة القراءة والكتابة بـ `try/catch`. إذا فشل التخزين، يستمر التحكم في الذاكرة دون كسر الصفحة، وتعود الحالة الافتراضية إلى مفتوح عند إعادة التحميل.

## 3. نقاط تنفيذية ملزمة

1. الروابط غير المتاحة حالياً تظهر معطّلة مع «قريباً» بالعربية و«Coming soon» بالإنجليزية، ولا تملك وجهة قابلة للتنقل.
2. رابط تفاصيل المنتج يظل معطّلاً؛ لا يُخترع slug ولا يُختار منتج افتراضي.
3. الشريط يظهر على Desktop وMobile، مع تسجيل أي تعارض بصري للمراجعة.
4. النصوص تخضع لترجمة AR/EN، والاتجاه RTL/LTR.
5. لا يعني هذا القرار الموافقة على التنفيذ أو الدمج. التنفيذ يحتاج مهمة مستقلة وPR ومراجعة لقطات وموافقة PO منفصلة قبل Ready وMerge.

## 4. تعارض مع وثيقة الـ Prototype

يذكر `docs/ui-reference/README.md` أن شريط «صفحات العرض» يُحذف قبل الإنتاج. هذا الوصف كان يعكس القرار السابق، وأصبح متعارضاً مع قرار PO الجديد. أُبقي النص التاريخي كما هو، وأضيف تحته تنبيه يربطه بهذا القرار البديل.

## 5. سجل الحالة

- قرار F2 السابق: **مُلغى بالقرار الجديد**.
- قرار شريط `.dn` داخل التطبيق الفعلي: **معتمد من PO**.
- التنفيذ البرمجي: **لم يبدأ ضمن هذا القرار التوثيقي**.
- المسارات غير المتاحة: **معطّلة — قريباً**.
